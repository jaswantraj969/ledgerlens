# Security review: API and worker

Date: 2026-11-12. Scope: the FastAPI service, the RQ worker, the Docker images and Compose file, and the dependencies. This is a review of the code as it stands, not a penetration test. Status per item: **pass** (already correct, with evidence), **fixed** (changed in this review, with a test), or **risk accepted** (known, reasoned, not changed).

Evidence logs are in `docs/progress/logs/`: `security-runtime-checks.log`, `security-gitleaks-history.log`, `security-pip-audit.log` and `security-npm-audit.log`.

| # | Item | Status | Evidence |
|---|---|---|---|
| 1 | Authentication on every route except the public ones | pass | `tests/api/test_route_auth.py` calls every route in the OpenAPI schema without credentials: all non-public routes return 401. Runtime: `GET /documents` without credentials gives 401. |
| 1a | Public routes | pass | `GET /health/live`, `GET /health/ready`, `GET /metrics`, `POST /auth/register`, `POST /auth/login`, `POST /auth/refresh`, and the OpenAPI pages (`/docs`, `/redoc`, `/openapi.json`). The list is fixed in `test_route_auth.py`. |
| 1b | Open registration | risk accepted | `POST /auth/register` creates a new, isolated organisation with one admin; it cannot join an existing one. It is rate-limited per client IP. Self-service sign-up is the intended model for a local prototype. |
| 2a | Upload size limit | pass | `max_upload_bytes`; at most limit + 1 bytes are read. `test_oversize_file_is_rejected`. |
| 2b | File type by content, not extension | pass | Magic bytes decide the type (PDF, JPEG, PNG); the name must also match the content. `test_extension_must_match_the_content`, `test_pdf_upload_…`, `test_png_and_jpeg_uploads_are_accepted`. |
| 2c | Page count limit | pass | `max_pages` checked with pdfium before storing. `test_too_many_pages_is_rejected`. |
| 2d | Image pixel limit | **fixed** | Images over 40 megapixels are refused (413, `image_too_large`) before OCR decodes them. `test_images_over_the_pixel_limit_are_refused_before_decoding`. |
| 3 | Path traversal in stored file names | pass | Uploaded names are display-only (`safe_filename`). Storage keys are `org/<uuid>/<sha256>`, generated by the server, and `LocalStorage._path` refuses any key that resolves outside the root. `test_path_traversal_in_the_filename_is_neutralised`. |
| 4a | Webhook HMAC signing and timestamp | pass | `X-LedgerLens-Signature: sha256=HMAC(secret, "<timestamp>.<body>")` with `X-LedgerLens-Timestamp`. The secret is shown once and is per hook. `test_a_finished_job_sends_a_signed_delivery…`. |
| 4b | Replay window | **fixed** | `verify()` added for receivers: constant-time comparison, and timestamps more than 300 s from the receiver's clock are rejected. Receivers should also drop repeated `X-LedgerLens-Delivery` ids. `test_a_fresh_correctly_signed_delivery_verifies`, `test_bad_or_stale_deliveries_do_not_verify`, `test_the_window_edge_is_inclusive…`. |
| 5a | Outbound webhook URLs: private and link-local addresses (SSRF) | **fixed** | Previously a deny-list (private, loopback, link-local, reserved), which missed shared address space (100.64/10), multicast and IPv4 inside IPv6. It is now an allow-list: every resolved address must be globally routable unicast, after unwrapping IPv4 inside IPv6. The check runs at creation and again at every delivery. https only. `test_hosts_resolving_to_non_public_addresses_are_refused` (13 addresses, including 169.254.169.254), `test_hosts_resolving_to_public_addresses_are_allowed`. |
| 5b | Redirects | pass | httpx does not follow redirects by default, and delivery creates its client without `follow_redirects`. A 3xx reply counts as a failed delivery. |
| 5c | DNS rebinding between the check and the connection | risk accepted | The host is resolved once for the check and again by httpx when connecting, so a host with a very short DNS lifetime could switch to a private address in between. Pinning the checked address would need a custom transport that keeps TLS name checks. Mitigations: https only, so the target must also present a valid certificate for the hostname; only admins can register hooks; and payloads carry ids and states, never document data. |
| 6a | Rate limiting on login | pass | Fixed window in Redis per email (`auth_rate_limit`); fails closed (503) without Redis. `test_login_rate_limit_triggers`. |
| 6b | Rate limiting on upload | pass | Per user, counted per file, batch uploads included (`upload_rate_limit`). `test_upload_rate_limit_triggers`. |
| 6c | Login limited per email, not per IP; refresh not limited | risk accepted | One IP can try many different emails. Passwords are hashed with Argon2, and the response is the same for unknown emails. Refresh tokens are random, high-entropy, rotated, and replay revokes the family (`test_replaying_a_used_refresh_token_revokes_the_family`). A per-IP login limit is a reasonable next step behind a trusted proxy. |
| 7 | No secrets in the repository | pass | gitleaks over the full history (136 commits, `--log-opts=--all`): no leaks. `.env` is ignored and was never committed; only `.env.example` is tracked. The JWT secret has no default (`LEDGERLENS_JWT_SECRET` is required by Compose). |
| 8 | Containers run as non-root | **fixed** | API and worker already ran as `app` (uid 10001). The web container ran as root (the Caddy image default); it now runs as `web` (uid 10002) on port 8080. The Postgres and Redis servers run as uid 70 and uid 999 (official images drop privileges). `test_containers_run_as_a_non_root_user`; runtime `id` in `security-runtime-checks.log`. |
| 9a | pip-audit | **fixed** | One finding: `litellm` 1.97.0 (CVE-2026-114612), pulled in only by the optional `llm` extra, which nothing imports or installs. The extra was removed; the lock file lost litellm and 15 packages only it needed, and no other version changed. Rerun: no known vulnerabilities. No unit test; the rerun log is the evidence. When hosted providers are built, add a patched litellm (1.100.4 or later). |
| 9b | npm audit | pass | 0 vulnerabilities (all dependencies, and production only). |
| 10 | `/metrics` reachable through the public web proxy | **fixed** | `/metrics` holds request timings and process counters, no document data. The API port is bound to 127.0.0.1, but Caddy proxied `/api/*`, so `/api/metrics` was public. The proxy now answers 404 for it; scrape the API service directly. `test_the_web_proxy_does_not_expose_metrics`; runtime: proxy 404, direct 200. |

## Not covered
- Penetration testing, fuzzing of the PDF and image parsers beyond the size and page limits, and denial-of-service limits on review and export endpoints.
- TLS: Compose serves plain HTTP on 127.0.0.1. A deployment needs TLS in front of the web container.
- The OpenAPI documentation is public; it shows the API's shape, not data.
